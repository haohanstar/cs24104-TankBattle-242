### 1.2 A 战斗引擎（姚于轩）

#### FR-01 坦克八方向移动、转向与地形碰撞

- 角色/端：A 战斗引擎 / 桌面端（Kotlin + LibGDX）
- 优先级：高
- 场景：玩家按方向键，坦克在 26×26 的地图里移动；碰到砖墙、钢墙、水、基地停下，冰面滑行，草丛可穿。
- 输入：方向输入（8 方向）、上一帧坐标 `(x, y)`、朝向 `dir`、速度 `speed`、当前地图版本。
- 输出：新坐标、新朝向、本帧是否发生碰撞；碰撞事件进 `STATE_SNAPSHOT`。
- 做法要点：按 X/Y 轴分开移动，每轴移动前查目标格；地形判断不在 A 里写，调 `MapService.isBlocked(rect, mover)` 和 `terrainAt(cell)`。
- 验收判据：8 个方向都能移动且朝向正确；AABB 分轴检测下撞墙不穿透（以 8 px/帧 的高速移动测试 20 次，0 次穿墙）；水域坦克不可进入、子弹可穿过；冰面松开按键后至少滑行半格；基地不可破坏、被击中即判负；草丛不阻挡且绘制在坦克上层。
- 来源：S2、S3
- 对应用例：UC-04

#### FR-02 射击、子弹与三类碰撞

- 角色/端：A / 桌面端
- 优先级：高
- 场景：玩家按射击键，坦克发射子弹；子弹在飞行中与坦克、其他子弹、地形发生碰撞。
- 输入：射击方向、武器参数（`damage`、`power`、`cooldown`）、当前帧内所有坦克与子弹的位置。
- 输出：子弹的生成/移动/销毁；命中结果（扣血、破坏图块、子弹抵消）；`GAME_OVER` 事件。
- 做法要点：坦克-坦克、坦克-子弹、子弹-子弹由 A 判定；子弹-地形由 B 的 `hitBullet(cell, power)` 判定，A 不重复写地形循环。
- 验收判据：三类碰撞各构造 10 组用例，判定结果与预期一致；速度 2 格/帧的子弹不穿透 1 格厚的砖墙；同一帧内两颗子弹相撞按“先创建者优先”规则结算且结果可复现；子弹飞出场外或存活超过 3 s 自动回收。
- 来源：S2、S3
- 对应用例：UC-04

#### FR-03 多武器：散弹、激光、追踪导弹

- 角色/端：A / 桌面端
- 优先级：高
- 场景：坦克拾取不同武器后切换射击方式；三种武器的伤害、冷却、弹药不同。
- 输入：武器配置表（`type`、`damage`、`cooldown`、`ammo`、`power`）、玩家已解锁武器列表。
- 输出：对应弹道与伤害；弹药与冷却状态。
- 验收判据：散弹一次发 3 颗、单颗伤害 1；激光穿透 1 层砖墙、冷却 1.5 s；追踪导弹在 30° 内自动修正朝向、命中率≥70%；三类武器的伤害/冷却/弹药全部来自配置表，改配置不改代码；弹药耗尽后回落到默认武器。
- 来源：S2
- 对应用例：UC-04

#### FR-04 AI 智能瞄准与弹道预测

- 角色/端：A / 桌面端
- 优先级：中
- 场景：AI 控制的坦克在移动目标出现时预判弹道，替代直线瞄准。
- 输入：目标位置与速度、子弹速度、障碍物分布（来自 `MapService.terrainAt`）。
- 输出：射击方向角；命中概率估计。
- 约束：AI 只输出“往哪打”，不接管移动与碰撞；模型/接口不可用时退回直线瞄准，游戏不中断。
- 验收判据：对匀速横向移动的目标，50 次射击命中率≥60%（直线瞄准同条件≤35%）；接口超时 500 ms 内退回直线瞄准且无报错；关闭 AI 瞄准后对局可正常完成。
- 来源：S2、S6
- 对应用例：UC-04

### 1.3 B 地图系统（姚帅）

#### FR-05 五类地形渲染 + Tiled 地图加载

- 角色/端：B 地图系统 / 桌面端
- 优先级：高
- 场景：进入对局时按 `map_id` + `version` 加载 `.tmx`，渲染砖墙、钢墙、水域、冰面、草丛和基地。
- 输入：`map_id`、`version`、`hash`、`.tmx` 文件、图块集 `maps/tiles.tsx`。
- 输出：`TileMap` 对象、渲染结果、地图元数据 `MapMetadata`。
- 约束：默认 26×26 格、单格 16×16 px（画布 416×416）；三层（`terrain` / `decor` / `objects`）；加载前比对 `hash`，不一致拒绝加载。
- 验收判据：5 类地形 + 基地各至少 1 张截图，颜色与图块属性一致；`arena_01`（26×26）在开发机加载耗时 <200 ms（取 30 次中位数）；`hash` 不一致时抛出 `MapVersionMismatch` 并提示更新，不进入对局；`.tmx` 缺少 `objects` 图层时报“地图缺少出生点”，回退默认图。
- 来源：S3
- 对应用例：UC-09

#### FR-06 地图编辑器 + mapcheck 校验

- 角色/端：B / 桌面端 + Python 3.12 校验 CLI
- 优先级：高
- 场景：地图作者在 Tiled 1.12.2 里编辑地图，保存后跑 `mapcheck`；校验不过的地图不能进游戏。
- 输入：`maps/*.tmx` 工程、图块属性、`maps/schema/map.schema.json`、难度参数。
- 输出：校验报告（是否通过、失败项、失败坐标）；退出码 0/1 供 CI 使用。
- 校验规则：出生点到基地存在通路；基地周围 ≥6 块砖；砖 15%~30%、钢 5%~12%、水 ≤10%、冰 ≤8%、草 5%~15%；两侧出生点路径长度差 ≤15%；无面积 >5% 的孤立区域；schema 校验 `additionalProperties=false`。
- 验收判据：构造 5 张错误地图（无通路 / 基地砖不足 / 砖比例超标 / 出现孤立区域 / 少 `objects` 图层），5 张全部被拦下并输出具体坐标；10 张正常地图 100% 通过；单张校验耗时 <1 s。
- 来源：S3
- 对应用例：UC-10

#### FR-07 AI 地图生成 + 平衡校验

- 角色/端：B / 桌面端（生成器） + Python（生成脚本）
- 优先级：中
- 场景：选定难度、尺寸、seed 后生成候选地图，自动跑 mapcheck，全部通过才输出。
- 输入：`difficulty`（easy/normal/hard）、`size`、`seed`、主题（草地/雪地/城市）。
- 输出：通过校验的 `.tmx`、校验报告、预览缩略图。
- 约束：生成器用 BSP + 约束修复，不让 LLM 直接输出瓦片；LLM 只把“难度描述”转成生成参数、解释校验报告；API 不可用退回内置参数表。
- 验收判据：每档 30 张、共 90 张，修复后 mapcheck 100% 通过；单张生成 <2 s；同 seed 同参数生成结果完全一致（`hash` 相同）；3 位同学盲测难度区分度≥3.5/5；断网时仍能生成 easy 档。
- 来源：S3、S6
- 对应用例：UC-10

### 1.4 C 对战房间（杨宇航）

#### FR-08 房间创建/加入/离开/准备/匹配

- 角色/端：C 对战房间 / Web 后端（Spring Boot + Netty）
- 优先级：高
- 场景：玩家登录后创建房间或从列表加入；满员拒绝；全员准备后房主开局。
- 输入：房间号或筛选条件（地图、人数、模式）、玩家 id、准备状态。
- 输出：房间状态、玩家列表、开局事件 `START`。
- 异常：房间不存在、房间满、重复加入、房主退出、准备超时（120 s）、房间密码错。
- 验收判据：上述 6 类异常各有明确提示码（`ROOM_NOT_FOUND`、`ROOM_FULL`、`ALREADY_JOINED`、`HOST_LEFT`、`READY_TIMEOUT`、`BAD_PASSWORD`）；创建到进入房间 P95 <1 s；重复加入幂等返回当前房间，不产生第二条记录；房主退出后按加入顺序移交房主，无房主时房间 5 min 后关闭。
- 来源：S2
- 对应用例：UC-02、UC-03

#### FR-09 WebSocket 状态同步 + 断线重连

- 角色/端：C / Web 后端
- 优先级：高
- 场景：对局中服务端每 tick 下发状态快照；客户端断线后带 `lastTick` 重连并补齐。
- 输入：客户端 `PLAYER_INPUT(tick, keys, dir)`、服务端权威状态。
- 输出：`STATE_SNAPSHOT(tick, tanks, bullets, items)`、`MAP_STATE(mapId, version, hash, destroyed)`。
- 约束：以服务端判定为准；客户端只做预测与表现。
- 验收判据：20 tick/s 下快照不丢序（tick 单调递增）；断线 30 s 内重连成功并追平到最新 tick，位置误差 ≤1 格；连续断网 10 次，10 次都恢复；重连期间对局不暂停其他玩家。
- 来源：S2
- 对应用例：UC-03、UC-04

#### FR-10 观战、录像回放、AI 解说

- 角色/端：C / Web 后端 + H5 观战页
- 优先级：中
- 场景：观战者以只读身份进入对局旁观；对局结束后可回放；AI 生成文字解说。
- 输入：`roomId` / `matchId`、观战请求；回放事件序列。
- 输出：只读 `STATE_SNAPSHOT`、回放时间轴、解说文本。
- 约束：观战客户端只能收不能发，任何输入消息直接丢弃；回放保存“初始地图 + 事件序列”，不存逐帧快照。
- 验收判据：观战端 5 人同时进入不影响对局 tick（误差 ≤1 帧）；观战者发送 `PLAYER_INPUT` 被服务端拒绝并记录日志；回放支持按 tick 定位（跳转后状态与顺序播放到同一 tick 一致）；回放可还原到与原局一致的地图破坏状态（对比 `destroyed` 集合 100% 一致）；解说可一键关闭，关闭后回放仍可用。
- 来源：S2、S5（I-03 要求只读与按 tick 跳转）
- 对应用例：UC-07、UC-08

### 1.5 D 道具升级（杨旭）

#### FR-11 道具生成/拾取/效果

- 角色/端：D 道具升级 / 桌面端
- 优先级：高
- 场景：对局中按时间或点位生成道具，坦克驶过即拾取，效果按配置生效。
- 输入：战局时间、道具候选点（来自 `MapService.freeCells()`）、玩家位置。
- 输出：`ITEM_SPAWN`、`ITEM_PICKUP` 事件与属性变化。
- 约束：道具只放在 `freeCells()` 返回的空格，不改写地形；同类道具同屏上限 3 个。
- 验收判据：道具落点 100% 在空格上（用 20 张地图 × 5 次生成验证）；拾取判定在 1 帧内生效；7 类道具效果与配置表一致；道具不改变地形（拾取前后 `hash` 不变）；同屏同类上限生效。
- 来源：S2
- 对应用例：UC-05

#### FR-12 升级树

- 角色/端：D / 桌面端
- 优先级：中
- 场景：玩家用战局内积分升级坦克属性，升级项按树状依赖逐级解锁。
- 输入：当前等级、积分、升级项 id。
- 输出：新属性值、已解锁列表。
- 验收判据：升级条件与效果全部来自配置；未满足前置的升级项不可点；升满一条分支需 3 级、总积分消耗与配置一致；升级后属性立即写入 `STATE_SNAPSHOT`，A 侧读到的是同一份数据。
- 来源：S2
- 对应用例：UC-06

#### FR-13 AI 道具投放

- 角色/端：D / 桌面端
- 优先级：中
- 场景：AI 根据战局给劣势方补强，投放更强道具，但有冷却和次数上限。
- 输入：双方积分差、剩余时间、已投放次数。
- 输出：投放建议（点位 + 道具类型）。
- 约束：单局最多 3 次；同一方连续 2 次不重复投放；AI 不可用时按固定规则“劣势方每小时 1 次”。
- 验收判据：触发条件可复现（相同战局数据得到相同建议）；单局投放次数 ≤3；AI 关闭时对局正常，且有兜底投放。
- 来源：S2、S6
- 对应用例：UC-06

### 1.6 E 大厅战队（杨宁宁）

#### FR-14 登录/好友/组队/战队/排行榜

- 角色/端：E 大厅战队 / 移动端 H5（Vue3）
- 优先级：高
- 场景：玩家在 H5 登录、加好友、组队、建战队、查排行榜。
- 输入：账号密码、好友/战队操作、赛季 id。
- 输出：`token`（2 h 有效）、好友列表、战队成员、排行榜分页。
- 验收判据：登录成功返回 `token` 与 `role`，错误密码返回 401；好友增删查各 1 组用例通过；战队上限 20 人，超员拒绝；排行榜按 `score` 降序、同分按 `win_rate` 排；H5 在 320/375/414 三种宽度下无横向滚动。
- 来源：S2
- 对应用例：UC-01、UC-11

#### FR-15 锦标赛 + AI 胜率匹配

- 角色/端：E / 移动端 H5 + C 服务
- 优先级：中
- 场景：管理员/玩家发起锦标赛，系统按胜率匹配对阵，生成对阵表。
- 输入：报名列表、赛季胜率、赛制（8 人单败 / 16 人单败）。
- 输出：对阵表、轮次、比赛结果回写。
- 验收判据：8 人赛生成 7 场对阵且无轮空错误；匹配后双方胜率差 ≤15%；对阵表可导出图片；结果回写后排行榜自动更新。
- 来源：S2、S6
- 对应用例：UC-12

## 2. 非功能需求

| 编号 | 类别 | 目标值 | 验证方式 | 失败阈值 |
|---|---|---|---|---|
| NFR-01 | 实时性 | 桌面端 60 FPS；局域网输入→状态同步 P95 <100 ms | 真机帧率叠加 + 客户端记录 `input_ts` 与 `snapshot_ts` 差值 | 连续 30 s <50 FPS 或 P95 >150 ms |
| NFR-02 | 地图性能 | 加载 <200 ms；AI 生成单张 <2 s | 计时脚本取 30 次中位数 | 加载 >300 ms 或生成 >3 s |
| NFR-03 | 并发 | 10 房间 / 50 玩家同时在线，错误率 <1% | 压测 5 min（模拟客户端） | 错误率 >3% 或出现房间错乱 |
| NFR-04 | 重连 | 断线 30 s 内恢复且状态一致 | 断网 10 次，记录恢复 tick 与位置误差 | 有 1 次超过 45 s 或位置误差 >2 格 |
| NFR-05 | 兼容性 | Win10/11；Chrome/Edge 最新版；H5 320/375/414 | 真机/浏览器各 3 组截图 | 任一环境白屏或布局错位 |
| NFR-06 | 安全 | 服务端权威判定；`token` 2 h；输入校验；防作弊 | 代码审查 + 12 组越权用例 | 出现客户端可改血量/积分 |
| NFR-07 | 可维护性 | 单测覆盖率 ≥60%（地图 ≥70%）；ktlint/detekt 0 error | 本地与 CI 报告 | 覆盖率 <50% 或有 error |
| NFR-08 | AI 降级 | AI/API 不可用时核心玩法不中断 | 断 API 测试，记录降级路径 | 断 API 后对局无法开始或崩溃 |

补充说明：

- NFR-01 的 100 ms 是局域网口径。公网（校园网）实测会到 150~250 ms，答辩时按局域网数据讲，不拿公网数据充数。
- NFR-02 只有地图模块有这条，B 模块单独背指标；第二次课补测量脚本。
- NFR-03 的 10 房间 / 50 玩家是按课程单机条件定的。AI 最初建议 1000 并发，按我们的部署条件（一台开发机 + 一台云主机）改成 50，写进 SRS 时保留这个取舍。
- NFR-05 不写“主流浏览器全兼容”，只列实际测过的三档宽度和两个浏览器。
